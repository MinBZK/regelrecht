## Context

A rule that departs from another rule often states the departure in terms of what it departs from. A law says a person eats two sandwiches; a policy says a person who is hungry eats twice as many. The policy's output is the number of sandwiches, and so is its input.

Both ways to model that failed with a `CircularReference`:

- **As an override** ([RFC-007](/rfcs/rfc-007)), the policy article declares `overrides` on the law's output and reads that same output through an input source. Reading it resolves the law's article, which applies the override, which reads the output again.
- **As a filling of an open term** ([RFC-003](/rfcs/rfc-003)), the law leaves the number open with a `default`, and the policy `implements` it. Reading the law's output resolves the open term, which executes the implementation, which reads the output again. RFC-003 records this as a law authoring problem the engine does not work around.

Neither is an authoring error. "In afwijking van artikel 1" and "gelet op artikel 1" both refer to what article 1 says without the rule that departs from it, and that value exists.

A second defect sat next to this one. A replacing override was applied after all actions of the overridden article had run. A later action of that article that read the overridden output (`plakjes_kaas: $aantal_boterhammen`) therefore read the general rule's value, while every other article read the replaced one.

## Decision

**A rule that reads the output it changes reads the value it departs from.** When an article reads an output through an input source, and that article

- declares a replacing override of that very output, or
- implements an open term of that law,

the output is evaluated with that override or implementation held back. For an override that is the general rule's value; for an implementation it is the law with the next implementation, or the `default` when there is none. The override or implementation then applies once, not again to its own input.

An override is held back for the output it replaces. An implementation is held back for every read of the law it fills in: an output of another article can depend on the term as much as the output of the article declaring it, and "gelet op" refers to the law as it stands without this filling.

A `voids` override is not included. An output that does not arise has no value to depart from, and reading it still yields the void with its ground ([RFC-041](/rfcs/rfc-041)).

**A replacing override takes effect where the output is set.** The overridden article's later actions read the replaced value, the same value every other reader gets. An output assigned more than once is replaced after its last assignment. An override that declares, as a parameter, an output its target article sets later cannot run there; it runs after the article's last action, as before, and only the readers after the article see its value.

Where an override applies is unchanged: an override from another law still applies only within the execution that law started ([RFC-007](/rfcs/rfc-007), as amended by [RFC-041](/rfcs/rfc-041)).

## Why

**The legal text already names the value.** "Twice as many" has a referent, and it is the number the law gives. Refusing to compute it made the most natural formulation of a policy unmodellable and pushed modellers to a workaround: a second output in the law that holds the base value. That changes the general law to accommodate the special one, which is the opposite of what an override and an implementation are for.

**One value per output per execution.** Before the second change, an article could see a different value for its own output than the rest of the execution did. That is a wrong outcome with a successful run, which is the kind of failure the engine exists to make impossible.

**Cycles stay caught.** A base read is keyed on what it holds back, so a second base read of the same output by another rule is a different resolution, and a base read that reaches itself again is still a cycle.

## Consequences

- A base read bypasses the per-execution cache: its value is not the output's value in that execution and must not be served as one, nor served from it.
- Everything evaluated under a base read is uncached, including laws that have nothing to do with the rule held back: telling what depends on it would cost more than it saves. A base read therefore costs a fresh evaluation of its whole dependency subtree, once per departing rule that reads what it changes.
- The replacement moves into the action loop through `LazyInputs::replace_output`; `apply_overrides` skips outputs already replaced there. Parameters a replacing override declares that are inputs of the overridden article are resolved before it runs.
