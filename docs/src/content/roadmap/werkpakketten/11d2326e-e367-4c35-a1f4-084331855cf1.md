toelichting: >-
  Verschillende manieren van analyseren die mogelijk worden gemaakt door het
  omzetten van wetgeving naar een uitvoerbare specificatie (executable
  specification). Deze analyses vallen uiteen in vier hoofdcategorieën:


  **1. Afhankelijkheidsanalyse (Dependency Analysis)**\

  Hierbij wordt onderzocht hoe wetten naar elkaar verwijzen via dependency
  graphs.


  Wat wordt geanalyseerd: De volledige keten van verwijzingen tussen
  verschillende regelingen (bijv. hoe de Wet op de zorgtoeslag afhankelijk is
  van de Zorgverzekeringswet en het belastingstelsel).

  Onderzoeksvragen/Doelen:

  - Welke data heeft deze regel daadwerkelijk nodig?

  - Van welke andere wetten is deze regel afhankelijk?

  - Is een verwijzing expliciet in de tekst vermeld, of is het een 'onzichtbare'
  interpretatiestap van de uitvoeringsorganisatie?

  Welke versie van een afhankelijke wet was actief op de relevante datum (ex
  tunc vs. ex nunc)?


  **2. Structurele Analyse (Program Analysis)**\

  Zodra wetten als logica zijn vastgelegd, kunnen formele methoden uit de
  informatica worden toegepast:


  - Completeness checking: Geeft de wet voor elke toegestane combinatie van
  inputs een gedefinieerde output, of zijn er gaten waardoor er geen besluit
  wordt genomen?

  - Consistency checking: Leveren dezelfde inputs tegenstrijdige resultaten op
  in verschillende ketens van afhankelijke wetten (bijv. door uiteenlopende
  definities van het begrip 'huishouden')?

  - Dead code detection: Welke takken/voorwaarden in de wet kunnen nooit worden
  bereikt, ongeacht de input? (Dit identificeert kandidaten voor intrekking).

  - Order-sensitivity detection: Maakt de volgorde van uitvoering uit wanneer
  meerdere wetten afhankelijk zijn van data die in de loop der tijd verandert?


  **3. Getrouwheids- en Kwaliteitscontrole (Fidelity & Quality Auditing)**\

  Dit is specifiek gericht op het proces waarbij taalmodellen (LLM's) helpen bij
  de vertaling van wetteksten naar code:


  - Reverse pass: Kan elk element in de code worden teruggevoerd naar een
  specifieke zin in de wettekst?

  - Fidelity audit: Zijn er voorwaarden weggelaten, zijn er elementen uit de
  Memorie van Toelichting (die niet bindend is) onterecht toegevoegd, of is de
  juridische basis onjuist?

  - Drift check: Is de vertaalde tekst exact de versie die van kracht was op de
  geldigheidsdatum van de specificatie?


  **4. Analyse van 'Gaten' (Gap Analysis/Annotation)**\

  Dit betreft het identificeren van zaken die (nog) niet in code te vatten zijn:


  Wat wordt geanalyseerd: Untranslatable constructs (bijv. bepalingen als "naar
  het oordeel van de minister" of complexe afrondingsregels die het systeem nog
  niet ondersteunt).


  Onderzoeksvragen/Doelen:

  - Waarom kan de huidige set operaties deze bepaling niet uitdrukken?

  - Welke nieuwe operaties moeten worden toegevoegd aan het format om dit gat te
  dichten? (Door suggesties over het hele corpus te aggregeren, kan men bepalen
  welke functies prioriteit hebben voor ontwikkeling).
